# CSQTTR: диагностика на Android

## Когда применять
Использовать только когда пользователь явно вызывает этот скилл по имени.
Обычное упоминание батареи или производительности не является вызовом.
Вызов разрешает диагностику в указанном объёме, но не произвольную установку
APK, изменение исходников, сервера, сетевых параметров или публикацию данных.
Это инструкция агенту, не фоновая служба и не техническая песочница.

## Начало
1. Прочитать применимый AGENTS.md. Соблюдать ограничения дисков и Git.
   В этом проекте работать на E:, не читать и не писать C:/D: без разрешения.
2. Найти корень текущего checkout и проверить git status. Не подменять его
   другим checkout молча. Скрипты находятся в scripts/energy относительно
   корня; сначала прочитать README.txt. Если их нет, объяснить проблему,
   не скачивать и не копировать неизвестную версию автоматически.
3. Уточнять только недостающие условия: RAM/CPU/АКБ, длительность, нагрузка,
   сравниваемые версии. Для новой задачи действовать по правилу плана AGENTS.md.
4. Проверить adb devices; при нескольких устройствах выбрать физический
   телефон однозначно. Каждая команда ADB должна содержать -s SERIAL.
   Не использовать сохранённые из старого чата IP, PID или координаты экрана.
5. Зафиксировать версию/package приложения, состояние туннеля, питания,
   яркость и её авторежим, температуру. Не выводить секреты и содержимое профилей.

## Сохранность профилей
- Не выполнять uninstall, pm clear, сброс данных или восстановление всего
  каталога поверх работающего приложения.
- Перед разрешённой установкой/заменой APK либо действиями с настройками
  сохранить приватную резервную копию в игнорируемую .local/diagnostics на E:.
  Проверить успешность команды и читаемость архива; один ненулевой размер
  не доказывает успешность резервного копирования.
- Для debuggable APK использовать run-as. Архивировать shared_prefs и
  необходимые files/databases, если существуют; учитывать WAL и согласованность
  базы. Не прерывать активный туннель без разрешения для согласованного снимка.
- Сохранить контрольные суммы настроек до/после обновления. Если изменились,
  выяснить причину, а не заявлять сохранность только по успешной установке.
- Keystore-ключи могут быть неэкспортируемыми: резервная копия файлов не
  гарантирует восстановление после удаления приложения. Обновлять поверх
  только совместимым подписанным APK. Если копирование недоступно, не делать
  потенциально разрушительных действий без решения пользователя.
- Режим чтения не требует принудительного изменения/остановки приложения.

## Режимы диагностики
### CPU
Для общей нагрузки использовать существующий лёгкий Perfetto-стенд.
Для поиска функций — Simpleperf с символами именно измеряемого Rust-ядра;
для пробуждений и расписания — отдельную подробную системную трассу Perfetto.
Проверять разрешения и поддерживаемые источники. Не обещать доступ к событиям,
которых нет на устройстве. Разделять Android-процесс и native-процесс туннеля.
Лёгкий scripts/energy не записывает подробные стеки и sched/wakeup события.

### RAM
Для Android-объектов предложить отдельную диагностическую сборку LeakCanary,
только с разрешения на её создание/установку. Для native-памяти — heapprofd,
проверив подключение к отдельному процессу и используемый аллокатор.
Сравнить память после одинаковых циклов подключения и закрытия экранов.
Рост RSS/PSS сам по себе не доказывает утечку: возможны кэши и удержание
памяти аллокатором. Нужны удерживаемые объекты/стеки выделений и повторяемость.

### Батарея
Использовать scripts/energy/Measure-Device.ps1, Analyze-Trace.ps1 и
Compare-Runs.ps1. Сначала Doctor. Сохранять стандартные проверки качества.
Реальные замеры проводить без зарядки, на физическом телефоне, от 300 секунд.
Smoke и эмулятор проверяют только работоспособность сбора.
Перед отключением USB проверить беспроводную связь, затем попросить отключить
кабель и подтвердить отсутствие всех источников питания через dumpsys battery.
Сравнивать одинаковую нагрузку, длительность, яркость и близкую температуру.
Учитывать кэш YouTube и объём трафика; одинаковое видео не гарантирует
одинаковую сетевую нагрузку. Не заявлять строгую причинность без контроля.
Подробные профилировщики и дампы RAM запускать отдельно от замера батареи.
Расход заряда относится ко всему телефону. CPU-секунды не являются энергией.
Не превращать непроверенные current/voltage единицы в якобы точные ватты.

## Безопасное завершение — также при ошибке или отмене
До включения беспроводного ADB подготовить процедуру очистки; в скриптах
использовать try/finally. При ручных шагах вести список изменений состояния.
1. Завершить только созданную этим запуском запись; забрать отчёты. Не
   завершать все процессы Perfetto или ADB на компьютере.
2. Восстановить согласованную версию приложения и изменённые для теста
   параметры. Сверить профили. Вернуть исходное состояние видео/туннеля,
   если пользователь не попросил другое.
3. Отключить беспроводную отладку телефона. Для legacy adb tcpip вернуть
   adbd в USB-режим командой adb -s SERIAL usb. Если включалась системная
   «Беспроводная отладка», выключить и её. Учитывать фактический способ связи.
4. Проверить исчезновение сетевого устройства/закрытие ранее открытого порта.
   adb disconnect разрывает связь ноутбука, но не выключает слушатель телефона.
   Offline или недоступный порт без успешной команды отключения не доказывает
   выключение. Если связь потеряна раньше, попросить отключить отладку вручную
   или подключить USB для завершения; явно сообщить о незавершённой очистке.
5. Не оставлять пароли, токены, IP серверов, дампы и трассы в отслеживаемых
   Git-файлах. Не публиковать и не загружать их во внешние сервисы.

## Отчёт
Указать версии, условия, длительность и повторы, CPU по процессам, заряд
телефона, температуру, ошибки/потери трассы и ограничения сравнения.
Отделять измерения от гипотез и от предложений изменения кода.
Подтвердить сохранность профилей, итоговую версию и состояние беспроводного ADB.
Дать локальные ссылки на отчёты. Сообщить число/хеши локальных коммитов, если
были изменения. Не менять сеть, Gooby, keepalive, число потоков, UDP-буферы
или сервер ради измерений без отдельного явного запроса.

## Примеры явного вызова
- `$csqttr-diagnostics Проверь CPU при YouTube; код и APK не меняй.`
- `$csqttr-diagnostics Проверь рост памяти после переподключений.`
- `$csqttr-diagnostics Сравни расход двух указанных APK, сохрани профили.`
