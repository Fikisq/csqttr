# Правила работы

## Диски
- Не читать, не изменять и не удалять файлы на дисках C: и D: без явного разрешения пользователя. Работать с проектом и артефактами на E:.
- Не обходить ограничение через WSL, ссылки, инструменты или подпроцессы. Если инструмент требует доступа к C: или D:, сначала объяснить необходимость и получить разрешение.

## Git и публикация
- Локальные операции Git разрешены.
- Отправка коммитов разрешена без отдельного запроса только в удалённую ветку `codex` репозитория Fikisq/csqttr.
- Не отправлять коммиты в удалённый `main` без явного разрешения пользователя.
- Не создавать PR в другие репозитории ни из какой ветки без явного разрешения.
- Любые прочие действия с удалённым Git (включая fetch, pull, push, создание/удаление веток и тегов) и публикации требуют разрешения. Разрешение на локальный коммит не означает разрешение на публикацию.

## Изменение → локальный коммит
- Каждое отдельное изменение сразу сохранять отдельным локальным коммитом, прежде чем начинать следующее.
- Правило относится к изменению, добавлению и замене логики функций, импортам, HTML, стилям, конфигурации, документации и тестам.
- Не объединять независимые изменения в большой коммит. Тесты конкретного изменения допустимо включать в тот же коммит.
- Проверять содержимое коммита; не включать APK, логи, резервные копии, токены, пароли и личные данные.
- Сохранять исходную точку для сравнения до/после. Не переписывать историю и не уничтожать чужие изменения ради отката.

## Порядок работы и отчётность
- Перед каждым запросом пользователя перечитывать применимый AGENTS.md.
- Перед новой отдельной задачей явно спрашивать, записывать ли её план в AGENTS.md. Продолжение текущего плана не требует повторного вопроса.
- Вести текущий план здесь; выполненные пункты отмечать [x] с хешами соответствующих локальных коммитов. Не отмечать проверку выполненной без фактического результата.
- Сообщения коммитов должны описывать конкретное изменение и его назначение. В отчёте указывать число сделанных локальных коммитов и их хеши; не выдавать локальные коммиты за опубликованные.
- Когда пользователь говорит, что результат устраивает, или просит закончить текущий план, удалить только текущий план работ, сохранив постоянные правила.
