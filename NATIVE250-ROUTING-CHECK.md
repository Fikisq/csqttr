Пользователь разрешил проверку телефона и временное переключение системного VPN
с Happ на CSQTTR с последующим возвращением Happ. Деплой и удаление сервера не выполнялись.
Сохранена свежая копия DataStore и архив файлов/shared_prefs приложения: SHA-256 архива
на телефоне и компьютере совпали, 18 записей TAR проверены. Данные между двумя чтениями
вокруг резервного копирования совпали. Невалидная первая попытка потокового TAR не
использовалась как резервная копия; проверенный архив получен отдельно.

Сценарии выполнялись через настоящий интерфейс приложения. Перед нажатиями проверялись
свежесть UI dump и фокус приложения. При переключении телефона пользователем в Happ
проверка остановилась; после подтверждения готовности продолжилась. Для возврата Happ,
который не отдавал успешный UI dump, использован свежий снимок экрана и проверка фокуса.

## Результаты маршрутизации

Chrome обновлял одну и ту же тестовую HTTPS-страницу, показывающую внешний IPv4.
Её первоначально открыл пользователь: автоматическое открытие через ADB было заблокировано
проверкой разрешений. Последующие обновления выполнялись кнопкой Chrome «Обновить».
Результат сверялся с активной VPN-сетью и диапазонами UID Android. Когда дерево Chrome
не возвращало текст страницы, ответ проверялся по сохранённому снимку экрана.

| Сценарий | Правило Android для Chrome | Фактический результат |
| --- | --- | --- |
| Все с VPN | Включён | Внешний IPv4 совпал с сервером CSQTTR |
| Без VPN: выбран Chrome | Исключён | Другой внешний IPv4, обход CSQTTR |
| С VPN: выбран только Chrome | Включён | Внешний IPv4 снова совпал с сервером |
| Без VPN: список очищен | Включён | Внешний IPv4 сервера, туннель продолжает работать |
| С VPN: выбрано другое приложение, Chrome не выбран | Исключён | Тот же прямой IPv4, что при исключении Chrome |
| С VPN: список очищен | Активная сеть CSQTTR отсутствует | Интерфейс «Отключено», сохранена диагностика «Whitelist пуст» |

Контрольный Яндекс Браузер включался в диапазоны UID для «Все с VPN» и пустого/не
содержащего его списка «Без VPN», исключался для «С VPN», когда его не выбирали.
Трафик самого Яндекс Браузера отдельно не запускался. Собственный UID CSQTTR исключён
из его VPN. Проверка пустого списка учитывает реальную активную сеть ConnectivityService:
сохранённые NetworkCapabilities в vpn_management сами по себе не означают работающий VPN.

Это проверка конкретных сценариев IPv4/HTTPS, а не всех приложений, IPv6, UDP, скорости
или длительной устойчивости. Фильтрация ТСПУ этим тестом не диагностируется.

## Порядок и сохранение выбора

- В тестовом профиле выбраны два приложения в порядке, отличающемся от алфавитного:
  выбранные строки отображались в порядке добавления.
- Снятое выделение возвращало приложение в алфавитную часть после оставшихся выбранных.
- Для «С VPN» оставлены два приложения, для «Без VPN» — одно. После перехода в
  «Все с VPN», закрытия и повторного открытия режим сохранился; оба набора выбора сохранились.
- Очистка изменяет только текущий набор. Проверено на телефоне дополнительно к прежним
  unit-тестам; новый запуск unit-тестов в этом продолжении не требовался и не выполнялся.

## Задержки интерфейса

Счётчики `dumpsys gfxinfo` сбрасывались перед каждым сценарием. Ниже общая статистика
кадров процесса приложения, без суммирования повторных таблиц отдельных окон.

| Сценарий | Кадры | Задержанные кадры Android | p50 / p95 / p99 |
| --- | ---: | ---: | --- |
| 10 переходов между пятью вкладками | 233 | 17 (7,30%) | 15 / 69 / 150 мс |
| 3 цикла клавиатуры в поиске приложений, ввод и удаление текста | 219 | 43 (19,63%) | 13 / 42 / 57 мс |
| 3 открытия/закрытия клавиатуры в поле вкладки «Туннель», без изменения поля | 160 | 29 (18,12%) | 20 / 32 / 65 мс |

Клавиатура появилась во всех шести циклах; ввод и удаление в поиске прошли.
Сценарии завершились без зависания. Подтормаживания воспроизвелись, исправленными не считаются.
Это время кадров, а не время от касания до ввода; статистика относится к CSQTTR, не к
процессу клавиатуры. Проверена debug-сборка под ADB, короткие серии без контрольной версии.
Причина задержек, вклад отдельных компонентов и улучшение производительности не установлены.
Экономия АКБ не измерялась. Следующее действие по этой проблеме — профилирование медленных
кадров и проверка конкретного исправления теми же сценариями.
